MusicFloat v14.50 —— Apple Music 歌词浮窗 + 全局快捷键
（Apple-Music-Hotkeys 修改版）

使用方法
1. 把压缩包完整解压到任意文件夹。
2. 直接运行 MusicFloat.exe（单文件，自带 .NET 运行时，不需要另外安装）。
3. 启动后出现设置窗口（或已按设置隐藏到托盘）；在设置里勾选“启用”并点“应用”即可显示歌词浮窗。

本版相对 14.49 的变化（Thriller → Beat It 的真正原因，已在本机复现并修好）
· 原因一：Apple Music 把整条艺人信息当成艺人串
  （"Michael Jackson — Thriller (25th Anniversary) [Deluxe Edition]"）。网易云搜索时直接用了整串，
  于是只搜到一个混搭条目「Beat It Thriller (25th Anniversary Remix)」。现在搜索前先按破折号取主艺人
  （"Michael Jackson"），和酷狗的处理方式一致。
· 原因二：标题匹配允许"包含"。那个混搭条目的标题里同时含 "Beat It" 和 "Thriller"，
  于是被当成 Thriller。现在标题只接受**精确匹配或前缀关系**（"thriller" ↔ "thriller25thanniversary"
  算同一首，"beatitthriller…" 不算）。
· 缓存格式升级到 4，之前那条错误的 52 行结果会自动作废重查。
· 新增 `LyricsService.LastTrace`（内存中的各路来源结果），便于定位串歌。

本机实测（真实网络，含 billing 艺人串）：
  Thriller（整串艺人）  54 行 / 54 行翻译，首句 "It's close to midnight…"
  Thriller（短艺人）    54 行 / 54 行翻译
  Beat It              69 行 / 58 行翻译，首句 "They Told Him…"（自身正确）
  Mockingbird         102 行 / 102 行翻译
  VOID                 32 行 / 32 行翻译（日文原文）

本版相对 14.48 的变化
· 修复「Thriller 仍被识别成 Beat It」：14.48 已经修正了匹配规则，但**旧歌词缓存**里还存着
  上一次错误匹配的结果（Beat It 的歌词挂在 Thriller 的键下）。缓存命中会直接返回，绕过所有
  新规则，所以看起来"没修好"。
  现在把缓存格式版本从 2 升到 3，**旧缓存条目在启动时自动丢弃并按新规则重查**，无需手动清理。
· 以后只要匹配规则再调整，都会同步提升这个版本号，避免旧结论一直生效。

本版相对 14.47 的变化
· 修复歌词解析在异常返回上崩溃：酷我返回 `{"data":null}`（无歌词）时，`JsonElement.TryGetProperty`
  会抛 `InvalidOperationException`（不是 JSON 异常，所以之前的重试/捕获都不管）。crash.log 里
  已有 8 次这类记录。现在所有 provider 的 JSON 解析都先校验 `ValueKind`，数组/空值/`data:null`
  都安全返回。
· 修复「Thriller 被识别成 Beat It」：本地化标题探测原本对**任何**标题都会替换，且无播放时长时
  直接信任商店返回顺序 —— 于是把同一张专辑里的另一首歌当成了译名。现在只接受**脚本不同**的
  映射（拉丁 ↔ 中文/日文/韩文），英文→英文的替换一律拒绝。
· 偶发闪退兜底：设置 → 通用新增「软件渲染」开关（重启生效）。WPF 硬件渲染在部分显卡驱动上会
  直接杀掉进程（日志里没有任何记录），开启后改用软件渲染规避。
· 诊断：新增 `LyricsSource` 日志，记录每首歌最终命中的来源（lrclib / netease / kugou / kuwo），
  出现「歌词串歌」时可据此定位。

实测（本机联网）：Thriller 54 行（首句 "It's close to midnight…"，非 Beat It）；无播放时长时
同样不串；Mockingbird 102/102、FMB 49/49、VOID 32/32 翻译保持正常。

本版相对 14.46 的变化（同为联网实测）
· 把「多条目录条目只取第一个」这个错误类型在所有数据源上统一修掉：
  - 网易云：**优先选带翻译的条目**（原来命中第一个有歌词的条目就返回，可能正好没有 tlyric），
    条目按匹配度排序，最多试 4 个；只有全都无翻译时才退回「有歌词无翻译」的那个。
  - 酷狗：命中曲目排序后取前 2 个，逐个查歌词（原来只试第 1 个，遇上无歌词版本就整首失败）。
  - 酷我：同样排序取前 2 个 musicId，逐个查歌词。
· 等待翻译的时间 1.6 s → 2.6 s（网易云要搜索 + 每条目一次歌词请求，原来容易来不及）。
· 诊断日志补全：`LyricsTranslationMiss` 现在带播放时长，并区分
  `no-data`（网易云没找到）/ `no-translation(lyric=长度)`（找到但无翻译）/ `pending` / `failed`。

本版相对 14.45 的变化（这一次是实际联网跑通验证过的）
· 修复「FMB 没有翻译」的真正原因：网易云同一首歌有多个条目，只有一个带歌词/翻译。
  之前只取「最匹配的那一个」——恰好是空歌词版本，于是整首没有翻译。现在按匹配度排序
  **依次尝试最多 4 个条目**，直到拿到有内容的歌词与 tlyric。
· 网易云增加备用域名（interface / interface3），单域名被 RST 时自动换下一个。
· 修复「VOID 被当成纯音乐」：占位判定原来要求“只有一行”，而实际返回是
  3 行（出品人 : … / 纯音乐，请欣赏 / 推广 : …）。现在只要**任意一行**是占位文案就判为占位，
  继续走商店探测；制作信息正则也补上了“出品人 / 推广 / 宣传 / 营销 / 版权 / 鸣谢”等。
· 移除两个已失效的数据源：QQ 音乐搜索（返回 500，需要签名）与 gdstudio 聚合接口（主机不可达）。
  它们此前每个切歌周期都在浪费往返请求。

  Emptiness and Catharsis 45 行 / 45 行有翻译
  Supernova（aespa）     76 行 / 76 行有翻译

本版相对 14.44 的变化
· 翻译诊断：拿不到翻译时，crash.log 会记一行
  `LyricsTranslationMiss: 曲名 | 艺人 | 网易云状态…`
  （状态为 has-translation / no-translation / failed / canceled / pending）。
· QQ 音乐：歌词请求补齐网页版参数（platform=yqq 等），并在接口未返回歌词时记录
  `LyricsQQ` 行（含 HTTP 状态、是否无歌词、是否只有歌词无翻译）。
· 聚合接口未选中曲目时记录 `LyricsAggregator`（含候选数量）。

本版相对 14.43 的变化
· 修复「部分歌曲（例如 Tink 的 FMB）有歌词但没有翻译」：从你的 crash.log 看，网易云
  （music.163.com）的连接被中断（`无法连接歌词服务器 music.163.com`），而翻译只在网易云
  与 QQ 音乐的返回里，所以整首歌都拿不到翻译。
  现在新增一个**国内可直连的聚合接口**（music-api.gdstudio.xyz，代理网易云曲库），在需要翻译时
  并发查询：它同样返回 `tlyric` 中文翻译，且不受 music.163.com 被阻断的影响。
· 聚合接口的选曲不放任时长（该接口不返回时长）：要求曲名精确/包含匹配 **且** 艺人匹配，
  避免选到同名翻唱。

本版相对 14.42 的变化
· 修复「切歌时程序未响应」：14.42 里解析酷我搜索结果的写法用了嵌套重复的正则，在几十到几百
  KB 的响应上会灾难性回溯（单次可达数秒），而且跑在 UI 线程上，于是每次切歌都卡住。
  现在改为一次线性扫描切片（跳过字符串字面量），并放到线程池执行；实测 22 KB / 120 条结果首次
  40 ms（含预热）、重复调用约 1.5 ms。
· 减少切歌时的请求量：酷我、QQ 音乐各自只试一个搜索候选（原来两个），五路并发时的网络压力减半。

本版相对 14.41 的变化
· 新增两个中国大陆可直连的歌词源：
  - 酷我音乐（搜索 + 逐行歌词，覆盖中文与国际曲库）；
  - QQ 音乐（搜索 + 歌词，且带 **trans 中文翻译**）。
  现在同时查询 LRCLIB / 网易云 / 酷狗 / 酷我 / QQ 音乐，五路并发，先命中者生效。
· 翻译来源不再只有网易云：网易云（tlyric）与 QQ 音乐（trans）任一给出翻译都会自动附加到每句；
  命中歌词但没有翻译时最多等待 1.6 秒。
· 酷我搜索结果是非标准 JSON（单引号、&nbsp; 实体），用宽松扫描解析，并按时长/艺人/曲名评分选曲，
  避免选到同名的翻唱或其它曲目。

本版相对 14.40 的变化
· 竖排歌词改为**紧贴窗口右侧**：两列（当前句 / 下一句）连同翻译整体右对齐到可用宽度边缘，
  间距仍保持约 9 px；每一块都会被限制在窗口内，不会超出被裁掉。窗口很窄时优先保证右边界，
  文字块宽度超过窗口时才回退到半窗布局。

本版相对 14.39 的变化
· 竖排翻译位置修正：翻译不再压在歌词上——当前句的翻译放在「下一句那一行的另一列」（右上），
  下一句的翻译放在「当前句那一行的另一列」（左下），两者都不会与任何歌词重合。
· 非单词语言的「左上右下」布局左右更紧凑：两列之间固定约 9 px 间距（本版起改为整体靠右），
  不再各自在半窗格子里居中而留下大片空隙（超长时会自动回退到半窗布局）。
· 继续修 void 被当成纯音乐：
  - 商店查询改为**最多 3 次请求**、只查日区/中国区；被商店限流（403/429）后暂停 3 分钟，
    避免越失败越发请求；
  - 成功解析的「本地化标题 → 原文标题」会记在内存里，同一首歌再次播放直接复用（不必再探测）；
  - 商店不可用时改用**酷狗按歌手泛搜 + 唯一时长匹配**作为第二意见（要求候选唯一，
    避免把同时长的兄弟曲目错认）；
  - crash.log 新增 `LyricsPlaceholder`（哪首歌被判成占位）与 `LyricsKugouTitle`（酷狗反查结果），
    便于定位。

本版相对 14.38 的变化
· 新增「清除歌词缓存」按钮（设置 → 歌词，在「重新查找歌词」旁边）：删除 lyrics-cache.json 与
  内存缓存并立刻重查当前歌曲。之前误匹配（例如被当成纯音乐）的曲目用它清一次即可。
· 修正把正常歌曲识别成纯音乐：之前只要某个来源返回「纯音乐，请欣赏」这类占位文案就立即当作
  结果。现在占位不再算命中——它会继续尝试其它来源，并按曲名到商店查原文标题后再查一次
  （例如 void →「空の箱」）；只有确实没有别的歌词时才显示占位。占位结果也不再写入缓存，
  避免错误结论一直留着。
· 再次加强 TOGENASHI TOGEARI 的 void / emptiness and catharsis / what to raise：
  商店查询先按「歌手 + 本地化曲名」搜（商店能把官方英译名映射到日文条目）；没有可用播放
  时长时，带曲名的查询直接信任商店返回顺序（此前要求专辑名匹配，而专辑名也被本地化，
  所以永远失败）；查询范围收敛到日区/中国区以适配单次 4.5 秒预算；单次查询预算由 3.25 秒
  放宽到 4.5 秒、重试总窗口 20 秒，让探测能跑完。失败仍会在 crash.log 记 LyricsTitleResolveMiss。

本版相对 14.37 的变化
· 「未识别到正在播放的 Apple Music 歌曲」等状态提示改为竖排列，和「纯音乐，请欣赏」一致
  （此前因为文案里有英文，会走横排单行）。
· 修复部分歌曲没有翻译（例如 蜘蛛糸モノポリー (feat. 初音ミク)）：网易云搜索此前直接拿带
  (feat. …) 的完整曲名，容易搜不到对应曲目。现在先用去掉括号内容的主标题 + 主艺人搜索，
  再用完整文本兜底；等待网易云返回翻译的时间也从 0.9 秒放宽到 1.6 秒。
· 再次修复 TOGENASHI TOGEARI 的 void / emptiness and catharsis / what to raise 找不到歌词：
  上一版的商店查询是在 3.25 秒预算耗尽后才开始的，经常还没发出请求就被取消；现在它与歌词
  查询**并行**发起，命中歌词即取消。带专辑/曲名的查询允许 ±6 秒的时长误差（Apple Music 与
  商店的时长常差 1-3 秒），歌手名是罗马音、目录是日文时不再因为名称对不上而放弃；拿不到
  播放时长时改用专辑名匹配。仍找不到会在 crash.log 记一行 LyricsTitleResolveMiss（含时长与
  专辑），方便定位。
· 修复快捷键切歌首次不生效（表现为当前歌从头播放）：此前一次跳转指令发出后不检查结果，
  Apple Music 队列未就绪时会把“下一首”执行成重播。现在发送后会检测曲目是否真的变化，
  未变化就再发一次（最多两次），会话失效时重建 SMTC 连接；播放/暂停也加了同样的一次重试。

本版相对 14.36 的变化
· 修复「有歌词却显示未找到」：Apple Music 会把日文等曲名本地化（例如 TOGENASHI TOGEARI
  的「空の箱」显示成 void、「空白とカタルシス」显示成 emptiness and catharsis），而歌词库
  只索引原文曲名。现在所有来源都查不到时，会按歌手/专辑到 iTunes 商店（日区/中国区/美区）
  用播放时长匹配同一首曲子，取回原文曲名后再查一次；卡拉 OK、翻唱条目会被排除。
· 修复不显示翻译：翻译只存在于网易云结果里，而此前只要 LRCLIB 先返回歌词就直接结束，
  永远拿不到翻译。现在命中歌词但没有翻译时，会等网易云的并行请求并附上翻译；
  已缓存的歌词若没有翻译，也会重查一次补上。
· 修复输入后「应用」按钮不亮：字号、翻译字号、开机恢复等待秒数与四个坐标输入框此前只在
  失去焦点时才更新设置，现在边输入边更新（文本仍只在失焦/应用时规范化）。
· 竖排四宫格里，翻译不再盖住下一句：当前句翻译在左下格，下一句翻译在右下格。

审查并修复的问题
· 项目原本无法编译：StartupService 使用了 System.IO 却没有 using。
· 每 0.25 秒强制置顶会盖住开始菜单 / Alt-Tab（绕过 14.35 的 shell 判断）。
· 关闭浮窗时窗口位置保存无效（已改为在 Closing 时保存），最后一次拖动/缩放不丢。
· 每次启动/每次点“应用”都会重写开机启动注册项，可能覆盖用户在 Windows 里手动禁用的状态；
  现在只有设置与实际注册状态不一致时才同步。
· 四宫格里较宽的翻译文本会被窗口右边缘裁掉。
· iTunes 预取用严格相等匹配当前曲目，常常匹配不到，预取形同虚设（改为与艺人/专辑一致的包含匹配）。
· 艺人变体在艺人为空时重复添加空串，导致重复请求。
· 网络失败耗尽重试后被显示成“本地歌曲 无歌词”，改成“未找到歌词”。
· 删除无用的分支与重复状态判断（设计不变）：水平单词分支里恒为假的翻译判断、窗口侧重复的预取去重、
  重试条件里重复的上下限、StartupService 的重复路径解析与四段重复清理代码。

14.35 及更早的要点
· 2×2 排版：当前句左上格内居中、下一句右下格内居中；长单词保持字号，越过格子也不会被裁。
· 关闭「半透明背景」时浮窗不接管鼠标（点击穿透）。
· 歌词匹配：歌名 + 艺人双重校验；切歌艺人串错自动重查；本地缓存带版本号。
· 连接失败自动重试（初次 + 3 次，15 秒内）；纯音乐等单句歌词靠右垂直居中。
· 作词/作曲等制作信息不再当作歌词；无底板时文字带描边；浮窗离屏时回到屏幕中央。

歌词浮窗操作
· 右键菜单（需开启背景）：打开设置 / 重新查找歌词 / 退出 MusicFloat。
· 开启背景后可直接拖动窗口；拖边缘可调整大小（位置尺寸会自动保存）。
· 每次查询会在 crash.log 记一行
  “LyricsResult: 歌名 | 艺人 | Found/NotFound/Unavailable | 行数”。
